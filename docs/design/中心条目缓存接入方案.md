# 中心条目缓存接入与运行约束

日期：2026-11-01。中心是可关闭的加速服务，App 启动、浏览、同步、富集均不依赖中心可用。

## 数据流与故障语义

- App 始终从本地 API/SQLite 读取界面数据。后台按最多 100 个条目批量查询中心，只发送 category/subject_id，不发送用户 ID、评分、短评或豆瓣 Cookie。
- 命中落本地 subjects，保留中心原始 fetched_ms、原始 cover_url、source=rexxar；不伪造 raw_json。图片经 App 本地代理访问豆瓣。
- 中心 miss 不排服务端抓取任务。App 本地 worker 处理缺失条目，原有限速、退避、熔断保持独立。
- 独立中心后台任务不受豆瓣熔断、类别退避、维度抓取优先级阻塞。本地 intro 也可升级；手工强制刷新绕过中心。
- 连接预算 800ms，总 HTTP 预算 3s。错误/限流/畸形或过大响应暂停中心查询 60s（尊重数字 Retry-After，限制到 30–300s，再加最多 15s 抖动）。错误不增加豆瓣重试次数。
- 成功查询的缺失条目 30 分钟后允许复查；已命中的完整本地数据不重复请求。启动有短随机延迟，批次间隔至少 1.5s。
- 每批仅持有 4s 的本地短租约，普通豆瓣抓取在该租约期间让行；超时、关闭开关会释放租约，进程崩溃则自动到期。两边通过 SQLite 写事务/条件更新协调，已运行的豆瓣抓取和强制任务不被中心接管。
- 设置中「使用中心详情缓存」即时生效并存入本地 app_preferences，跨启动随机端口持久。关闭会取消在途中心请求。启动配置关闭时 UI 不允许覆盖。

## HTTP 契约

`POST /api/v1/subjects/batch` 是独立公共只读路由，只有显式开启导出服务才挂载。线上 URL 为 `https://weimo.ink/douban/api/v1/subjects/batch`。

请求：`{"items":[{"category":"movie","subject_id":"1292052"}]}`。

响应：`{"schema_version":1,"items":[...],"missing":[...]}`。items 为规范化条目，包含 category、subject_id、title、original_title、year、aka、url、cover_url、rating_value、rating_count、meta、fetched_ms、status、source。

- 只导出 status=ok 且 source=rexxar 的数据；不读 records，不合成 intro，不触发中心抓取。
- 每批最多 100 个键；数字 ID 长度 1–20，category 为 movie/book/music。重复键去重。
- 请求最大 16 KiB，响应最大 256 KiB，单条最大 64 KiB。格式错误 400，体积超限 413；服务繁忙/查询超时/响应过大返回 429 或 503，App 自动回退。
- 中心数据完整覆盖请求键，客户端拒绝未知/重复/遗漏键、协议版本变化、不合法字段或 URL；不接受跳转。
- 服务端使用独立只读连接池（1 连接、100ms 等待），批量查询总时限 500ms。按联合主键查询，取完释放连接再编码响应。
- 后端独立总限额 2 次/秒、突发 2、处理并发 2。网页鉴权/限流预算不用于此接口，App 不携带管理 Token。

## 网页优先的 nginx 保护

`ops/subject-cache/http.conf` 放入 nginx http 上下文；`location.conf` 用于两个精确路径 `/douban/api/v1/subjects/batch`、`/douban-admin/api/v1/subjects/batch`，避免从另一个前缀绕过限额。

- nginx 总限额 1 次/秒、突发 2；每 IP 1 次/秒、突发 1，超额立即 429。
- 两个前缀共享最多 2 个传输连接；每响应限速 32 KiB/s。nginx 每个新响应存在初始发送额度，因此这不是严格的全机 64 KiB/s 总带宽上限；结合 1 次/秒的总请求限制，按约 64–96 KiB/s（0.52–0.79 Mbps）的量级保守评估。JSON 使用既有 gzip。
- 这是一组保守初值，不是按云套餐比例验证的上限。云套餐带宽尚未确认；确认后以网页优先、中心使用约 10%–20% 出口为调参目标。
- 响应缓冲开启、禁用临时文件，避免慢客户端占用后端数据库资源。App 收到限流后走本地抓取，中心不会排长等待队列。
- 不扩大网页现有 IP 额度，也不让 App 通过中心下载封面。现有网页管理 Token 的权限拆分仍是独立事项；本功能不向 App 分发该 Token。

## 配置与部署

| 配置 | 服务器默认 | App 默认 |
|---|---|---|
| SYNC_SUBJECT_CACHE_SERVE | false | 强制 false |
| SYNC_SUBJECT_CACHE_URL | 未设置，不查询中心 | 官方完整 batch URL |

显式设置 `SYNC_SUBJECT_CACHE_URL=''` 永久禁用本次进程的中心查询。自托管可覆盖 HTTPS 地址；HTTP 仅允许回环联调。设置偏好读取失败时启动继续，中心保持关闭。

数据库启用 WAL，原有数据保留。**运行中的数据库备份必须用 SQLite backup API；不能只复制 .db 而遗漏 -wal。** 回滚旧二进制可继续读取 WAL 数据库，不删除新增偏好/租约表，也不手工删除 WAL 文件。

先构建验证服务端及两个 App 入口；服务端发布采用独立源码快照，保存原二进制、nginx 配置和 SQLite 一致性备份。安装 nginx 限制并通过 `nginx -t`，配置服务开关后重启后端、平滑 reload nginx。先验证网页与缓存，再交付本地 App 构建；公开版本发布另按 txy 部署手册执行。

紧急关闭中心导出：将 systemd 覆盖配置设为 `SYNC_SUBJECT_CACHE_SERVE=false` 后 daemon-reload/restart。App 会自动本地回退，网页原 API 仍工作。

## 验收

集成测试使用本地 mock，不访问真实豆瓣：命中免抓取、intro 升级、保留时间和封面地址、中心断连/超时/429/错误 JSON/超大响应、本地回退、关闭取消与重启持久化、强制刷新/较新本地数据保护、租约避免重复抓取及崩溃到期、30 客户端 600 次缓存请求不消耗网页额度。

混合负载在本地隔离实例进行：30 个 App 的批量请求和网页读请求并发，缓存允许拒绝；网页不得新增 429/5xx，网页 API P95 相比同等网页负载基线增加不超过 100ms。线上仅进行有界烟雾检查，不对生产执行无上限压测。
