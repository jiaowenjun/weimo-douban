# 本地 MCP 使用指南

连接微墨·豆瓣的本地 MCP 后，你可以让 AI 助手查询电脑中已备份的书影音记录，查找作品与短评、统计收藏，或整理年度回顾。**App 完全退出后，仍可查询最后一次同步的数据。**

## 可以怎样使用

- 「找出我今年看过并打了五星的电影，附上当时的短评。」
- 「我读过哪些村上春树作品？按标记日期列出来。」
- 「我收藏的电影里，出现最多的导演有哪些？」
- 「根据我的评分和短评，整理年度书影音回顾，注明账号、统计范围和最近同步时间。」

MCP 只读取已有备份，不会修改评分、短评或豆瓣账号，也不会启动同步。需要最新数据时，先打开 App 完成同步，再让助手重新查询。

## 接入前准备

1. **安装微墨·豆瓣 v0.5.2 或更新版本**。可从[下载页](https://gitee.com/jiaowenjun/weimo-douban/releases)获取；旧版本安装包不含 MCP 程序。
2. **打开 App，至少完成一次同步**，确认能在 App 中浏览自己的记录。
3. **选择支持本地 stdio MCP 的 AI 助手**，在保存 App 数据的这台电脑上运行，并允许它启动配置中的程序。

本地连接使用 App 附带的 `weimo-douban-mcp`，不需要另装 Node.js 或 Python，也不需要服务器地址、端口或访问凭证。查询本身无需联网；AI 助手能否离线使用，取决于它采用的模型。

## 生成连接配置

打开终端或 PowerShell，运行安装包中的 MCP 程序，并加上 `--print-config`。它会输出这台电脑上的连接配置。

### macOS

如果 App 安装在「应用程序」目录，在终端运行：

```bash
"/Applications/微墨·豆瓣.app/Contents/MacOS/weimo-douban-mcp" --print-config
```

如果 App 安装在其他位置，将命令中的 App 路径换成实际位置，保留路径两侧的引号。

### Windows

在 App 安装目录中找到 `weimo-douban-mcp.exe`，在 PowerShell 中运行以下命令，将路径替换为实际位置：

```powershell
& 'C:\实际安装目录\weimo-douban-mcp.exe' --print-config
```

保留开头的 `&` 和路径两侧的引号。该程序用于连接 AI 助手，不提供独立窗口。

### 将配置添加到助手

命令输出的结构如下，**请使用你电脑上实际生成的内容**，不要直接使用示例中的占位路径：

```json
{
  "mcpServers": {
    "weimo-douban": {
      "command": "/实际安装位置/weimo-douban-mcp",
      "args": ["--data-dir", "/实际应用数据目录/ink.weimo.douban"]
    }
  }
}
```

在 AI 助手的 MCP 设置中添加这个服务。支持 `mcpServers` 格式的客户端可合并这段配置；已有其他服务时，保留它们的条目。不同客户端可能使用不同的配置结构，或提供设置表单：

| 设置项 | 填写内容 |
|---|---|
| 名称 | `weimo-douban`，也可以自行命名 |
| 传输方式 | stdio／本地命令 |
| 命令 `command` | 生成配置中的完整程序路径 |
| 参数 `args` | 生成配置中的参数列表，包含 `--data-dir` 和数据目录 |

程序路径和参数分别填写。JSON 中的路径使用完整路径；Windows 的反斜杠转义以生成结果为准。不要依赖客户端自动展开 `~` 或 `%APPDATA%`。

保存配置后，启用或重新连接服务，确认能发现下方五个工具。助手会按需启动 MCP 程序，无需一直开着终端。

`--print-config` 只生成配置，不会自动修改助手设置，也不检查数据库是否已有数据。配置生成成功后，仍需完成首次查询来确认连接可用。

## 第一次查询

可以直接把这段话交给助手：

> 请使用 weimo-douban，先列出本地可以查询的账号。如果有多个账号，让我选择；只有一个时使用该账号。然后统计它已同步的电影、图书和音乐标记数量，并说明最近同步时间。如果数据还在同步，请注明结果可能不完整。

助手应先调用 `list_users`，取得实际豆瓣用户 ID（`uid`），再查询选定账号。即使只有一个用户，后续查询也需要填写 `uid`。

| 工具 | 用途 |
|---|---|
| `list_users` | 列出本地账号、标记数和最近同步时间，作为查询的第一步 |
| `search_marks` | 查询具体作品的标记、个人评分与短评，支持筛选及分页 |
| `get_subject` | 查看已缓存的作品详情，例如豆瓣评分、导演或作者；可使用搜索结果中的作品编号 |
| `get_stats` | 统计符合条件的全部标记，包括类别、状态、个人星级和标记年份 |
| `list_facets` | 统计导演、类型、国家／地区、作者等维度，也可获取精确筛选所需的名称 |

如果同时连接了远程 MCP，提问时明确指定本地服务 `weimo-douban`。网页版与桌面 App 分别保存数据，两边的记录数量和同步时间可能不同。

## 筛选与查询示例

日常使用时，用自然语言说明需求即可，助手负责填写工具参数。需要检查调用详情或排查错误时，可参考下面的参数对象。

先调用 `search_marks` 做最小查询，将占位文字替换为 `list_users` 返回的实际 ID：

```json
{
  "uid": "从 list_users 获取的实际 ID"
}
```

确认成功后，再查询「2026 年标记为看过、个人评分五星的电影」：

```json
{
  "uid": "从 list_users 获取的实际 ID",
  "category": "movie",
  "status": "collect",
  "my_rating_min": 5,
  "my_rating_max": 5,
  "marked_from": "2026-01-01",
  "marked_to": "2026-12-31",
  "limit": 20
}
```

这些字段直接放在参数对象顶层，不要额外包进 `filter` 或 `page`，也不要把整个对象变成字符串。`search_marks`、`get_stats`、`list_facets` 每次调用都需要 `uid`，相邻工具调用中的 ID 不会自动沿用。

| 想筛选什么 | 使用方式 |
|---|---|
| 电影、图书、音乐 | `category` 分别为 `movie`、`book`、`music` |
| 看过／读过／听过，正在进行，想看／想读／想听 | `status` 分别为 `collect`、`do`、`wish`；结果取决于本地实际已同步的内容 |
| 我给出的星级 | `my_rating_min`／`my_rating_max`，范围为 1–5 星；未评分记录不匹配星级范围 |
| 某段时间标记的作品 | `marked_from`／`marked_to`，格式为 `YYYY-MM-DD`，包含起止日期 |
| 某年上映、出版或发行的作品 | `release_year_min`／`release_year_max`；未知年份不匹配年份范围 |
| 标题、别名或短评中的文字 | `query`，按字面子串搜索，最多 200 字符 |
| 指定导演、类型、地区或作者 | 先用 `list_facets` 获取精确值，再通过 `facets` 筛选，例如 `[{"name":"directors","value":"王家卫"}]` |

`facets` 支持 `genres`、`countries`、`directors`、`press`、`authors`、`translators`、`singers`，多个条件需同时满足。它们是作品信息维度，不是用户自定义标签。

需要完整计数时，让助手用 `get_stats` 传入相同的筛选条件；`get_stats` 不需要 `limit` 或 `offset`。「今年看过」应使用今年的**标记日期**范围，不能替换为作品上映年份。

## 正确理解结果

- **总数与当前页不同**：`total` 是匹配总数，`items` 是当前页内容。搜索默认返回 20 条，每页最多 100 条；继续读取时使用返回的 `next_offset`。不要将第一页当作完整清单。
- **个人星级与豆瓣评分不同**：个人评分为 1–5 星，豆瓣公共评分是另一项作品信息。「我打五星」应筛选个人星级。
- **数据新鲜度取决于同步**：查看 `last_synced_at` 或 `sync`。同步进行中的结果可能尚不完整；翻页期间如果有新数据同步，各页内容也可能变化。
- **缺失详情不会自动补抓**：尚未同步的评分或作品详情可能为空；部分详情来自已有简介的整理。可以先在 App 中更新数据，再让助手重查。
- **关闭 App 不等于刷新数据**：完全退出 App 后，MCP 仍可查询已有备份，但不会替 App 继续同步。只关闭窗口、仍留在菜单栏或系统托盘时，App 的同步可继续运行。

整理年度回顾或榜单时，可以要求助手注明账号、日期范围、筛选条件、匹配总数和同步时间，并区分记录事实与助手的推测。

## 确认数据目录

通常直接使用生成的配置即可。若能连接但查不到 App 中的记录，可检查配置里的 `--data-dir` 是否指向实际保存备份的目录：

| 平台 | 默认数据目录 |
|---|---|
| macOS | `~/Library/Application Support/ink.weimo.douban` |
| Windows | `%APPDATA%\ink.weimo.douban` |

表中使用系统路径简写方便查找；连接配置里应填写展开后的完整路径。`--data-dir` 指向包含 `douban_export.db` 的文件夹，不是数据库文件本身。

如果使用自定义数据目录，可在生成配置时显式指定，例如 macOS：

```bash
"/Applications/微墨·豆瓣.app/Contents/MacOS/weimo-douban-mcp" \
  --data-dir "/实际保存备份的目录" --print-config
```

更改这个参数只会切换查询位置，不会搬迁数据或创建备份。请先确认该目录中的数据能被配套版本 App 正常使用。

## 常见问题

| 现象 | 处理方法 |
|---|---|
| 找不到 `weimo-douban-mcp`／`.exe` | 确认 App 为 v0.5.2 或更新版本，并检查实际安装位置；程序随 App 安装包提供 |
| 终端报路径不存在、命令无法启动 | 检查完整程序路径；在终端保留路径引号，Windows PowerShell 保留开头的 `&`；客户端的命令与参数分别填写 |
| 生成了配置，但助手无法连接 | 确认客户端支持 stdio、可以启动本机程序，且已保存并启用连接；展开错误详情检查路径和参数 |
| 提示数据库尚未初始化 | 先在 App 中同步一次，再确认 `--data-dir` 指向实际数据目录 |
| 提示数据库结构不兼容 | 使用配套版本 App 完成初始化或升级，再重新连接 MCP |
| 连接成功，但账号、数量或短评不符合预期 | 核对数据目录、`uid`、筛选范围、分页与同步时间，确认使用的是本地连接 |
| 提示缺少 `uid`，调用详情却显示 `{}` | 查看实际参数及客户端解析错误；按「只传 uid → 加一个条件 → 逐项增加」重试，必要时换模型或客户端做对照 |
| 提示数据库忙、查询超时或候选记录过多 | 稍后重试，并按类别、日期或关键词缩小范围；需要计数时使用 `get_stats`，需要具体记录时分页读取 |
| App 更新或移动后，助手仍用旧工具、无法启动 | 重新生成配置并核对路径，断开旧 MCP 连接后再连接，使助手启动新程序 |

在一次 ZCode + GLM-5.3 会话中，曾出现单参数成功、多参数解析失败后被客户端替换为 `{}` 的情况。不能只凭助手说「忘记传 uid」就认定原因，也不能删除原本需要的条件后，把未筛选结果当作答案。完整排查方法见 [AI 查询问题排查](troubleshooting.md)。

反馈时记录客户端和模型版本、App 版本、发生时间、工具名称、实际参数及原始错误，并隐去私人短评和个人路径。

## 数据与访问权限

连接后的助手可以读取所选本地数据库中各账号的已同步标记和短评。查询结果会进入助手的上下文，是否发送给云端模型取决于助手设置；本地保存并不等于助手只在本机处理数据。

MCP 不提供修改、删除、触发同步或直接导出 CSV 的工具。更新记录和导出 CSV 请使用 App。保留安装包中的 MCP 程序路径，App 升级后重新连接，方便程序与数据版本保持一致。

需要查询网页版数据，可选择[远程 MCP 使用指南](remote-guide.md)。自行构建或使用原生 macOS 实验版本，请参阅 [MCP 开发说明](README.md#构建与验证)。
